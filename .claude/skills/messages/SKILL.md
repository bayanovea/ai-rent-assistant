# Переписка в Messenger

Это единственный проход, который трогает реальный Messenger пользователя —
чужие люди читают то, что здесь отправляется. Работай размеренно, каждое
сообщение перед отправкой показывай целиком, ничего не отправляй без
явного подтверждения пользователя на весь пакет разом.

**Классифицируешь ответы только ты — состояние диалога считает код.**
`messages.derive_state` в `messages.py` — единственное место, где факты
превращаются в `state`/`needs_action`. Твой результат — только факты:
`pets_answer`, `viewing_proposed`, `proposed_times`, `listing_gone`,
`unusual`. Не пытайся сам решить, что показывать в колонке «Ждёт меня» —
это работа `derive_state`, и если факты те же, вывод всегда один и тот же.

**Фан-аута нет специально.** Треды короткие (десяток строк текста), в
отличие от фото или веб-поиска по зданию — гонять их через сабагентов
только чтобы спрятать контекст было бы чистым накладным расходом. Читай
batch и пиши результат сама, без `Task`/`Agent`.

## Часть А — синк и разбор ответов

### 1. Синк

```sh
rent-assistant messages sync
```

Тянет папку Marketplace из реального Messenger (headless), никогда не
открывает тред без положительной датировки от 20.09.2026 или новее — см.
`CLAUDE.md`. В конце — сколько синкнуто, сколько пропущено как старые,
сколько с новым неразобранным ответом, сколько не сопоставлено с
объявлением (`no_listing_match` — обычно значит, что объявление снято
продавцом: карточки в треде уже нет).

Если команда остановилась на сообщении про PIN сквозного шифрования —
это не баг, это реальная защита Messenger. **Не пытайся обойти сама.**
Скажи пользователю: нужна headed-сессия, он вводит PIN вручную (см.
`docs/messages.md`), и остановись — дальше без него не продолжить.

### 2. Собрать батч на классификацию

```sh
rent-assistant messages classify-batch
```

Печатает путь вида `.../ai/messages-batch-YYYYMMDD-HHMMSS.json`. Пусто —
скажи об этом и остановись, часть Б не относится к этому шагу.

### 3. Прочитать и классифицировать

Прочитай batch целиком. Каждый элемент — `{thread_id, reply_hash, fb_id,
listing_title, messages}`. `messages` — список `{direction, text}` в
хронологическом порядке; `direction: "out"` — то, что писал пользователь
(или это же авто-сообщение), `"in"` — ответ от продавца/агента.

Для каждого элемента определи факты **только по тексту `in`-сообщений**,
не выдумывая:

- `pets_answer`: `"allowed"` / `"not_allowed"` / `"unclear"` — явный ответ
  на вопрос про питомцев. Нет вопроса или ответа — `"unclear"`.
- `viewing_proposed`: `true`, если продавец назвал время или спросил,
  когда удобно посмотреть. `proposed_times` — список того, что он назвал
  (свободный текст, как в сообщении, не парси в даты).
- `listing_gone`: `true`, если ответ говорит, что жильё уже сдано/снято с
  публикации.
- `unusual`: `true` для всего, что не укладывается в «да/нет про животных»
  и «предложил время» — просьба доп. информации (как «пришлите фото
  собаки»), запрос на WhatsApp, встречный вопрос не по существу, отказ по
  другой причине. Это то, что реально нужно показать пользователю.

Не ставь несколько взаимоисключающих флагов бездумно — если ответ и
называет время, и говорит «но животных нельзя», выставь оба
(`pets_answer: "not_allowed"`, `viewing_proposed: true`); `derive_state`
сам решит приоритет (см. `messages.derive_state` — `unusual`/`listing_gone`
перевешивает всё, `not_allowed` перевешивает предложенное время).

Пиши результат в JSON-файл рядом с batch, **массив** объектов:

```json
[
  {
    "thread_id": "8000000000000001",
    "reply_hash": "<дословно из batch>",
    "facts": {
      "pets_answer": "unclear",
      "viewing_proposed": false,
      "proposed_times": [],
      "listing_gone": false,
      "unusual": true
    },
    "summary": "Продавец попросил фото собаки"
  }
]
```

`reply_hash` — переписать дословно из batch, не пересчитывать: `apply`
сверяет его с текущим состоянием треда и пропускает запись, если тред
успел получить новый ответ после того, как batch был собран.

### 4. Применить

```sh
rent-assistant messages classify-apply <путь к результату>
```

### 5. Экспорт и отчёт

```sh
rent-assistant export
```

Отчитайся коротко: сколько разобрано, и по каждому, что попало в
needs-action — id, заголовок, причина (`viewing_time` / `pets_declined` /
`unusual_reply` / `no_listing_match`), последняя реплика. Для
`pets_declined` и `listing_gone`-подобных случаев предложи готовую
команду, а не сделай сама:

```
rent-assistant reject <fb_id> --reason "хозяин: животных нельзя"
```

Решение отклонять или нет — за пользователем, не за тобой: предложи
команду и остановись, не выполняй её сама.

## Часть Б — первое сообщение

Пользователь описывает выборку текстом («весь shortlist», «shortlist и
longlist в Bang Tao», список id). Переведи это в флаги `rent-assistant messages
send`:

- «весь shortlist» → `--status shortlist`
- «shortlist и longlist» → `--status shortlist --status longlist`
- «в Bang Tao» / «в районе X» → добавь `--district "X"`
- список id → `--ids <id1> --ids <id2> ...` (игнорирует `--status`)

### 1. Показать черновики

```sh
rent-assistant messages send --status shortlist
```

Без `--apply` команда ничего не отправляет — только печатает все черновики
целиком (кто, объявление, текст) и список уже пропущенных (уже написано,
уже в логе, уже есть переписка). Покажи пользователю ровно то, что
напечатала команда — не пересказывай, не сокращай текст сообщений.

### 2. Подтверждение — обязательно на весь пакет

Спроси пользователя (`AskUserQuestion` или явным текстовым вопросом),
отправлять ли показанные черновики — по одному подтверждению на весь
пакет, не поштучно. Без явного «да» не переходи к следующему шагу.

### 3. Отправить

```sh
rent-assistant messages send --status shortlist --apply --yes
```

`--yes` пропускает внутреннее `click.confirm` — подтверждение уже получено
на предыдущем шаге, от пользователя, а не от команды. Команда сама
выдерживает джиттер между отправками и останавливается на `--cap`
(по умолчанию 10 за прогон); при обрыве сессии (логин истёк) — уже
отправленные записаны в лог и в стадию «Написал», повторный запуск их не
продублирует.

### 4. Отчёт

Сколько отправлено, сколько не удалось (и что с ними делать — обычно
просто перезапустить `messages send` тем же выбором, уже отправленные
сами пропустятся). Стадия «Написал» и колонка «Этап» появляются в
экспорте автоматически — напомни прогнать `rent-assistant export`, если ты его
ещё не запускала на этом шаге.
